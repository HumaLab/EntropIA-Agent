# Research archive failures

Research Agent runs over one or several corpora often end with archive batches without claims and an unclear error.
Goal: the run should not fail; when it does, show a clear message and a retry button, like batch processing.

## Specs

- S1. A research run over one or several corpora must not lose archive batches: "lo ideal es que no falle".
- S2. When a run fails, the user sees a clear message: "si falla tenga un mensaje claro".
- S3. A failed run or batch offers a retry button: "y un botón de reintento, como se hace en los procesameintos por lotes".
- S4. The error currently shown and judged unclear, verbatim: "Limitaciones\nsalida de archivo no parseable; lote registrado sin claims\nDegradación del pipeline: Salida inválida de asistente_archivo: la salida no contiene JSON recuperable (asistente_archivo, 4 veces)."

- S5. Decision (L13): when an archive batch still fails after being split, the run pauses with a clear message naming the batch, and Resume retries that same batch. No evidence is skipped. Option chosen verbatim: "Pausar y ofrecer Reanudar (recomendado)".
- S6. Scope (L13): engine only for now; option chosen verbatim: "Motor ahora (T2, T3, T5)". T4 (desktop) waits.
- S8. Decisions (L17): a NEW Settings tab "Agente"; ALL parameters including internal algorithm constants; desktop work in a new worktree from origin/main.
- S7. Every agent parameter is configurable in the Agent tab of Settings, verbatim: "quiero que todos los aprametros del agente s epeudan configurar en la solapa agente de configuración". (L16)
